# Получение данных в реальном времени

Обычный HTTP работает по модели **Request → Response**.

Инициатором обмена данными всегда является клиент.

Если серверу необходимо самостоятельно уведомить клиента о новых данных (например, о новом сообщении в чате), используются специальные механизмы обмена данными в реальном времени.

## Polling

Самый простой способ получения обновлений.

Клиент через определенные интервалы времени отправляет запрос на сервер.

Например, каждые 5 секунд:

```http
GET /messages
```

Если появились новые данные, сервер возвращает их.

### Преимущества

- простая реализация;
- работает практически везде;
- не требует специальных протоколов.

### Недостатки

- большое количество пустых запросов;
- лишняя нагрузка на сервер;
- задержка между появлением события и его получением.

---

## Long Polling

Long Polling — развитие обычного Polling.

Если новых данных нет, сервер не отвечает сразу, а удерживает HTTP-соединение открытым.

Как только появляются новые данные, сервер отправляет ответ.

После получения ответа клиент сразу открывает следующий запрос.

Такой подход:

- уменьшает количество пустых запросов;
- сокращает задержку получения данных.

Однако каждое сообщение по-прежнему требует создания нового HTTP-запроса.

---

## WebSocket

WebSocket — отдельный протокол, предназначенный для постоянного двустороннего обмена данными.

Соединение начинается как обычный HTTP-запрос.

После успешного **HTTP Upgrade** дальнейший обмен происходит уже по протоколу WebSocket (`ws://` или `wss://`).

После установки соединения:

- клиент может отправлять сообщения в любой момент;
- сервер также может отправлять сообщения в любой момент.

Такой режим называется **Full-Duplex**.

### Где используется

- чаты;
- онлайн-игры;
- совместное редактирование документов;
- биржевые терминалы;
- системы мониторинга;
- видеозвонки (совместно с WebRTC).

---

## Server-Sent Events (SSE)

SSE (Server-Sent Events) позволяет серверу отправлять события клиенту по уже открытому HTTP-соединению.

В отличие от WebSocket, соединение является **односторонним**.

Сервер может отправлять сообщения клиенту, но клиент не может использовать это соединение для отправки данных обратно.

Если клиенту необходимо отправить данные серверу, используется обычный HTTP-запрос.

В браузере SSE работает через API `EventSource`.

### Где используется

- уведомления;
- изменение статуса заказа;
- поток событий;
- мониторинг логов;
- курсы валют;
- биржевые котировки.

---

# Сравнение подходов

| Технология   | Соединение                    | Направление передачи       | Когда использовать                                            |
| ------------ | ----------------------------- | -------------------------- | ------------------------------------------------------------- |
| Polling      | HTTP                          | Клиент → Сервер → Клиент   | Простые приложения, редкие обновления                         |
| Long Polling | HTTP                          | Клиент → Сервер → Клиент   | Когда WebSocket недоступен, но нужны более быстрые обновления |
| WebSocket    | WebSocket (`ws://`, `wss://`) | Двустороннее (Full-Duplex) | Чаты, игры, совместная работа, биржи                          |
| SSE          | HTTP                          | Только Сервер → Клиент     | Уведомления, ленты событий, мониторинг                        |

---

# WebSocket vs SSE

| WebSocket                                         | SSE                                                     |
| ------------------------------------------------- | ------------------------------------------------------- |
| Двустороннее соединение                           | Передача только от сервера к клиенту                    |
| Отдельный протокол (`ws://`, `wss://`)            | Работает поверх HTTP                                    |
| Обе стороны могут отправлять сообщения            | Клиент отправляет данные обычным HTTP                   |
| Требует собственной логики переподключения        | Автоматическое переподключение встроено в `EventSource` |
| Лучше подходит для чатов, игр и совместной работы | Лучше подходит для уведомлений и потоковых обновлений   |

---

# Частые ошибки

❌ Считать, что WebSocket работает поверх HTTP.

HTTP используется только для установки соединения (HTTP Upgrade). После этого обмен идет по отдельному протоколу WebSocket.

❌ Думать, что SSE может заменить WebSocket.

SSE поддерживает передачу данных только от сервера к клиенту.

❌ Использовать WebSocket там, где достаточно обычного HTTP.

Постоянное соединение требует ресурсов как на клиенте, так и на сервере.

❌ Считать, что Long Polling — это постоянное соединение.

После каждого ответа соединение закрывается, а клиент открывает новое.

---

# Что важно запомнить

- **Polling** — периодический опрос сервера.
- **Long Polling** — сервер удерживает запрос до появления новых данных.
- **WebSocket** — постоянное двустороннее соединение после HTTP Upgrade.
- **SSE** — постоянный поток данных только от сервера к клиенту.
- Выбор технологии зависит от характера обмена данными: если нужен двусторонний обмен — WebSocket, если только уведомления от сервера — SSE.
