# HTTP

HTTP (HyperText Transfer Protocol) — это прикладной протокол, определяющий правила обмена данными между клиентом и сервером.

Несмотря на название, по HTTP могут передаваться не только HTML-документы, но и любые другие данные:

- JSON;
- изображения;
- видео;
- PDF;
- архивы;
- бинарные файлы.

Взаимодействие строится по модели **Request → Response**.

Клиент отправляет запрос, сервер обрабатывает его и возвращает ответ.

## HTTP Request

HTTP-запрос состоит из нескольких частей.

### URL

URL определяет адрес ресурса, к которому обращается клиент.

### Пример

```text
https://api.example.com/users/15?page=2
```

URL может содержать:

- протокол;
- домен;
- порт;
- путь;
- query-параметры.

### HTTP Method

HTTP-метод определяет, какое действие необходимо выполнить над ресурсом.

Наиболее распространенные методы:

| Метод     | Назначение                               |
| --------- | ---------------------------------------- |
| `GET`     | Получение данных                         |
| `POST`    | Создание ресурса                         |
| `PUT`     | Полная замена ресурса                    |
| `PATCH`   | Частичное обновление ресурса             |
| `DELETE`  | Удаление ресурса                         |
| `OPTIONS` | Получение информации о доступных методах |

#### GET

Используется для получения данных.

Особенности:

- не изменяет состояние сервера;
- обычно не содержит Body;
- может кешироваться.

#### POST

Используется для создания ресурса.

Данные обычно передаются в теле запроса.

#### PUT

Полностью заменяет существующий ресурс.

### Пример

```json
{
  "name": "Alex",
  "age": 25
}
```

#### PATCH

Изменяет только переданные поля.

### Пример

```json
{
  "age": 26
}
```

#### DELETE

Удаляет ресурс.

#### OPTIONS

Используется для получения информации о возможностях сервера.

На практике чаще всего встречается при **CORS** в качестве **Preflight Request**.

### Request Headers

Заголовки содержат дополнительную информацию о запросе.

Наиболее распространенные:

- `Authorization`;
- `Content-Type`;
- `Accept`;
- `Cookie`;
- `Origin`;
- `Referer`;
- `User-Agent`.

Часть заголовков автоматически добавляется браузером, часть задается приложением.

### Request Body

Тело запроса используется для передачи данных на сервер.

Чаще всего применяется с методами:

- `POST`;
- `PUT`;
- `PATCH`.

Формат данных определяется заголовком `Content-Type`.

Наиболее распространенные значения:

- `application/json`;
- `multipart/form-data`;
- `application/x-www-form-urlencoded`;
- `text/plain`.

## HTTP Response

После обработки запроса сервер отправляет ответ.

Ответ также состоит из нескольких частей.

### Status Code

HTTP-статус определяет результат обработки запроса.

| Группа | Назначение            |
| ------ | --------------------- |
| `1xx`  | Информационные ответы |
| `2xx`  | Успешное выполнение   |
| `3xx`  | Перенаправления       |
| `4xx`  | Ошибки клиента        |
| `5xx`  | Ошибки сервера        |

Наиболее распространенные статусы:

| Код                         | Значение                      |
| --------------------------- | ----------------------------- |
| `200 OK`                    | Успешный запрос               |
| `201 Created`               | Ресурс создан                 |
| `204 No Content`            | Ответ без тела                |
| `301 Moved Permanently`     | Постоянное перенаправление    |
| `302 Found`                 | Временное перенаправление     |
| `400 Bad Request`           | Некорректный запрос           |
| `401 Unauthorized`          | Требуется аутентификация      |
| `403 Forbidden`             | Недостаточно прав             |
| `404 Not Found`             | Ресурс не найден              |
| `409 Conflict`              | Конфликт данных               |
| `422 Unprocessable Entity`  | Ошибка валидации              |
| `500 Internal Server Error` | Внутренняя ошибка сервера     |
| `502 Bad Gateway`           | Ошибка промежуточного сервера |
| `503 Service Unavailable`   | Сервер временно недоступен    |

### Response Headers

Ответ также содержит заголовки.

Наиболее распространенные:

- `Content-Type`;
- `Content-Length`;
- `Cache-Control`;
- `Set-Cookie`;
- `ETag`;
- `Content-Encoding`.

Через заголовки сервер сообщает браузеру дополнительную информацию о полученных данных.

### Response Body

В теле ответа сервер возвращает данные.

Это может быть:

- JSON;
- HTML;
- изображение;
- PDF;
- поток данных;
- бинарный файл.

## Query Parameters

Не все данные передаются через тело запроса.

Для `GET` параметры обычно передаются непосредственно в URL.

### Пример

```text
/users?page=2&sort=name
```

Чаще всего Query Parameters используются для:

- фильтрации;
- поиска;
- сортировки;
- пагинации.

Передавать конфиденциальные данные через URL не рекомендуется.

Даже при использовании HTTPS URL может сохраняться в логах серверов, прокси и систем мониторинга.

## Простые и Preflight-запросы

При выполнении кросс-доменных запросов браузер разделяет их на две группы.

### Простые запросы

Не требуют предварительной проверки.

К ним обычно относятся:

- `GET`;
- `HEAD`;
- `POST` (только при определенных значениях `Content-Type` и без нестандартных заголовков).

### Preflight Request

Если запрос использует потенциально опасный метод (`PUT`, `PATCH`, `DELETE`) или нестандартные заголовки, браузер сначала автоматически отправляет запрос `OPTIONS`.

Сервер должен подтвердить, что такой запрос разрешен.

После этого браузер отправляет основной запрос.

Подробно этот механизм рассматривается в теме **CORS**.

## Идемпотентность

Идемпотентность означает, что повторное выполнение одного и того же запроса приводит к одинаковому результату.

Идемпотентными считаются:

- `GET`;
- `PUT`;
- `DELETE`;
- `HEAD`;
- `OPTIONS`.

`POST` идемпотентным не является, поскольку повторный запрос может создать новый ресурс.

## HTTP и HTTPS

Сам HTTP не шифрует передаваемые данные.

Поэтому современные приложения практически всегда используют **HTTPS**, который работает поверх TLS и обеспечивает:

- шифрование данных;
- проверку подлинности сервера;
- защиту от подмены данных.

Тема HTTPS обычно рассматривается отдельно.

## Частые ошибки

❌ Считать, что `GET` запрещено иметь Body.

Спецификация этого не запрещает, однако большинство клиентов и серверов игнорируют тело `GET`-запроса.

❌ Думать, что `POST` всегда означает создание ресурса.

Спецификация не связывает `POST` исключительно с созданием данных.

❌ Путать `401 Unauthorized` и `403 Forbidden`.

`401` означает отсутствие или недействительность аутентификации.

`403` означает, что пользователь аутентифицирован, но не имеет необходимых прав.

❌ Передавать конфиденциальные данные через Query Parameters.

URL может попасть в историю браузера, серверные логи и системы аналитики.
