# HTTP-кэширование

HTTP-кэширование позволяет повторно использовать ранее загруженные ресурсы.

Если ресурс не изменился, браузеру не нужно скачивать его заново — можно использовать локальную копию.

Это:

- уменьшает задержки;
- снижает нагрузку на сервер;
- экономит сетевой трафик.

## Виды кэширования

### Strong Cache

Браузер использует ресурс из локального кэша без обращения к серверу.

Например:

```http
Cache-Control: max-age=3600
```

Это означает, что ресурс можно использовать в течение часа.

Пока срок действия не истек, сетевой запрос не выполняется.

### Validation Cache

После истечения срока действия браузер может проверить, изменился ли ресурс, вместо повторной загрузки.

Для этого используются:

- `ETag`;
- `Last-Modified`.

При повторном запросе браузер отправляет:

- `If-None-Match`;
- `If-Modified-Since`.

Если ресурс не изменился, сервер отвечает:

```http
304 Not Modified
```

После этого браузер использует уже сохраненную локальную копию.

# Cache-Control

`Cache-Control` — основной заголовок управления HTTP-кэшированием.

Наиболее распространенные директивы:

### `max-age`

Определяет время жизни ресурса.

```http
Cache-Control: max-age=3600
```

### `no-cache`

Разрешает хранить ресурс в кэше, но перед использованием требует проверить его актуальность у сервера.

Название может сбивать с толку: кэширование не запрещается, обязательна только валидация.

### `no-store`

Полностью запрещает сохранять ресурс.

Обычно используется для конфиденциальных данных, например страниц интернет-банка.

### `public`

Разрешает кэширование как браузером, так и промежуточными прокси.

### `private`

Разрешает кэширование только в браузере пользователя.

# Версионирование файлов

Статические ресурсы (JavaScript, CSS, изображения) обычно публикуются с хэшем в имени файла.

Например:

```text
app.a8f23d.js
vendor.1f9c42.css
```

После нового релиза имя файла меняется.

Это позволяет задавать очень большой срок жизни:

```http
Cache-Control: max-age=31536000
```

Поскольку URL изменился, браузер скачает новую версию файла, а не будет использовать старую.

# Эволюция HTTP

За время существования HTTP появилось несколько основных версий протокола.

Каждая из них решала ограничения предыдущей.

## HTTP/1.1

Особенности:

- поддерживает Keep-Alive;
- использует несколько TCP-соединений к одному домену (обычно 6–10);
- поддерживает pipelining, который практически не используется.

Главная проблема — **Head-of-Line Blocking**.

Если один запрос задерживается, остальные в этом соединении вынуждены ждать.

Поэтому раньше часто использовали:

- объединение JavaScript в один файл;
- CSS-бандлы;
- CSS-спрайты;
- domain sharding.

## HTTP/2

Главное нововведение — **мультиплексирование**.

Несколько запросов могут одновременно передаваться по одному TCP-соединению.

Также появились:

- бинарный протокол;
- сжатие заголовков (HPACK);
- приоритизация потоков;
- Server Push (сейчас практически не используется).

Благодаря мультиплексированию необходимость объединять множество файлов стала значительно меньше.

## HTTP/3

HTTP/3 работает поверх протокола **QUIC**, который использует UDP.

Основные преимущества:

- более быстрое установление соединения;
- отсутствие блокировки всего соединения при потере одного пакета;
- лучшая работа в мобильных сетях;
- быстрое восстановление после смены сети (например, Wi-Fi → LTE).

Несмотря на использование UDP, передача остается надежной, поскольку QUIC самостоятельно реализует подтверждение доставки, повторную отправку и контроль порядка пакетов.

# Сравнение версий HTTP

| Характеристика        | HTTP/1.1               | HTTP/2                   | HTTP/3               |
| --------------------- | ---------------------- | ------------------------ | -------------------- |
| Транспорт             | TCP                    | TCP                      | QUIC (UDP)           |
| Соединения            | Несколько TCP          | Одно TCP                 | Одно QUIC            |
| Формат                | Текстовый              | Бинарный                 | Бинарный             |
| Мультиплексирование   | ❌ Нет                 | ✅ Есть                  | ✅ Есть              |
| Head-of-Line Blocking | Полностью присутствует | Частично (на уровне TCP) | Практически устранен |
| Скорость              | Ниже                   | Выше                     | Наиболее высокая     |

# Частые ошибки

❌ Считать, что `no-cache` запрещает кэширование.

На самом деле ресурс можно хранить в кэше, но перед использованием необходимо проверить его актуальность у сервера.

❌ Думать, что `304 Not Modified` возвращает содержимое файла.

Ответ `304` не содержит тело. Браузер использует уже сохраненную локальную копию.

❌ Считать, что HTTP/2 всегда открывает несколько TCP-соединений.

Основная идея HTTP/2 — использовать одно TCP-соединение с несколькими потоками.

❌ Думать, что UDP означает ненадежную передачу.

В HTTP/3 надежность обеспечивает протокол QUIC, а не TCP.
