# OSI Model

Модель OSI (Open Systems Interconnection) — это эталонная модель взаимодействия сетевых устройств, разделяющая процесс передачи данных на независимые уровни.

Каждый уровень решает свою задачу, предоставляет сервис вышестоящему уровню и использует сервис нижестоящего.

На практике Интернет работает по модели TCP/IP, однако именно модель OSI используется для объяснения принципов передачи данных и поиска сетевых проблем.

## Уровни модели OSI

| Уровень     | Назначение                                   |
| ----------- | -------------------------------------------- |
| Physical    | Передача битов по физической среде           |
| Data Link   | Передача кадров между соседними устройствами |
| Network     | Маршрутизация пакетов между сетями           |
| Transport   | Доставка данных между приложениями           |
| Application | Взаимодействие приложений                    |

## Physical Layer

Физический уровень отвечает за передачу битов по физической среде.

На этом уровне еще нет понятий IP, TCP или HTTP — передаются только электрические, световые или радиосигналы.

Средой передачи могут быть:

- витая пара;
- оптоволокно;
- Wi-Fi;
- мобильные сети.

Основные задачи:

- передача сигнала;
- кодирование сигнала;
- синхронизация устройств;
- борьба с помехами;
- выбор среды передачи.

### Особенности

**Витая пара**

Жилы скручиваются между собой для уменьшения электромагнитных помех и взаимных наводок.

**Оптоволокно**

Передача данных происходит с помощью света.

Для увеличения пропускной способности используется технология **WDM (Wavelength Division Multiplexing)**, позволяющая передавать несколько потоков данных одновременно на разных длинах волн.

**Wi-Fi**

Передача осуществляется по радиоканалу.

Для уменьшения количества коллизий используются механизмы управления доступом к среде передачи, а современные стандарты Wi-Fi дополнительно применяют OFDMA и MU-MIMO.

## Data Link Layer

Канальный уровень отвечает за надежную передачу данных между двумя соседними устройствами.

Если физический уровень передает поток битов, то канальный объединяет их в **Frame (кадры)**.

На этом уровне работают:

- MAC-адреса;
- Ethernet;
- коммутаторы (Switch).

Основные задачи:

- формирование кадров;
- физическая адресация (MAC);
- обнаружение ошибок передачи;
- управление доступом к среде передачи.

### Frame и Packet

Важно различать эти понятия.

- **Frame** — единица передачи канального уровня.
- **Packet** — единица передачи сетевого уровня.

Во время передачи IP-пакет инкапсулируется в Ethernet-кадр.

```text
Frame
├── MAC Header
├── IP Packet
└── CRC
```

### CRC

Для обнаружения ошибок в конец кадра добавляется контрольная сумма (**CRC**).

Получатель повторно вычисляет CRC и сравнивает результат.

Если значения отличаются, кадр считается поврежденным.

CRC позволяет обнаружить ошибки передачи, но не исправляет их.

## Network Layer

Сетевой уровень отвечает за доставку пакетов между различными сетями.

Именно здесь появляется понятие IP-адреса.

Основные протоколы:

- IPv4;
- IPv6;
- ICMP.

Основные задачи:

- логическая адресация;
- маршрутизация;
- выбор оптимального маршрута;
- доставка пакетов между сетями.

### Routing

Маршрутизаторы анализируют IP-адрес назначения и определяют, куда отправить пакет дальше.

Фактически Интернет представляет собой огромную сеть маршрутизаторов, по которым пакет постепенно движется к получателю.

### TTL

Поле **TTL (Time To Live)** ограничивает время жизни IP-пакета.

Каждый маршрутизатор уменьшает значение TTL на единицу.

Когда TTL становится равным нулю, пакет удаляется.

Именно поэтому `traceroute` позволяет определить путь пакета через сеть.

## Transport Layer

Транспортный уровень отвечает за доставку данных между двумя приложениями.

На этом уровне уже не имеет значения, через сколько маршрутизаторов прошли данные.

Главная задача — доставить их приложению.

Основные протоколы:

- TCP;
- UDP.

### TCP

TCP обеспечивает надежную доставку данных.

Для этого используются:

- Three-way Handshake;
- нумерация сегментов;
- подтверждения получения (ACK);
- повторная передача потерянных сегментов;
- управление потоком;
- контроль перегрузок.

TCP применяется там, где потеря данных недопустима:

- HTTP / HTTPS;
- FTP;
- SMTP;
- базы данных.

### UDP

UDP не устанавливает соединение и не гарантирует доставку данных.

Пакеты просто отправляются получателю без подтверждений и повторных передач.

Это делает UDP быстрее TCP.

Используется там, где важнее минимальная задержка:

- видеозвонки;
- онлайн-игры;
- стриминг;
- DNS.

## Application Layer

Прикладной уровень определяет формат обмена данными между приложениями.

Именно на этом уровне работают протоколы, с которыми ежедневно взаимодействует frontend-разработчик.

Наиболее распространенные:

- HTTP / HTTPS;
- WebSocket;
- DNS;
- FTP;
- SMTP;
- IMAP.

### HTTP

Используется для передачи HTML, JSON, изображений, файлов и других ресурсов.

Именно здесь находятся:

- методы (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`);
- статус-коды;
- заголовки;
- cookies.

### DNS

DNS преобразует доменное имя в IP-адрес.

Без DNS браузер не смог бы определить, куда необходимо отправить запрос.

### WebSocket

WebSocket работает поверх TCP и позволяет установить постоянное двустороннее соединение между клиентом и сервером.

После установки соединения сервер может самостоятельно отправлять сообщения клиенту без дополнительных запросов.

## Инкапсуляция данных

При передаче каждый уровень добавляет к данным собственный заголовок.

Этот процесс называется **инкапсуляцией**.

```text
HTTP Message
      ↓
TCP Segment
      ↓
IP Packet
      ↓
Ethernet Frame
      ↓
Bits
```

На принимающей стороне происходит обратный процесс — **деинкапсуляция**.

## Частые ошибки

❌ Считать, что Интернет работает по модели OSI.

На практике используется стек протоколов TCP/IP, а модель OSI применяется как эталонная модель для объяснения принципов работы сети.

❌ Путать MAC-адрес и IP-адрес.

MAC используется внутри локальной сети, а IP — для маршрутизации между сетями.

❌ Считать, что CRC исправляет ошибки.

CRC позволяет только обнаружить повреждение данных.

❌ Думать, что TCP гарантирует мгновенную доставку данных.

TCP гарантирует надежность и порядок доставки, но не минимальную задержку.

❌ Путать Frame, Packet и Segment.

Каждый из них относится к своему уровню сетевой модели.
