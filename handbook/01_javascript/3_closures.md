# Замыкания (Closures)

Замыкание (Closure) — это механизм JavaScript, благодаря которому функция сохраняет доступ к своему внешнему лексическому окружению даже после завершения выполнения внешней функции.

Именно замыкания позволяют функциям "помнить" переменные, которые существовали в момент их создания.

## Как создается функция

При создании функции JavaScript сохраняет не только ее тело.

Внутри функции также сохраняется скрытая ссылка на внешнее лексическое окружение — **[[Environment]]**.

Важно понимать, что эта ссылка сохраняется **в момент создания функции**, а не во время ее вызова.

Именно поэтому функция всегда "помнит", где была создана.

## Вызов функции

При вызове функции движок создает новый **Execution Context (контекст выполнения)**.

Он содержит:

- собственное лексическое окружение (Lexical Environment);
- значение `this`;
- объект `arguments` (для обычных функций);
- служебную информацию, необходимую движку.

После завершения выполнения функции ее Execution Context удаляется из стека вызовов.

Однако само лексическое окружение может продолжить существовать, если на него остались ссылки.

## Lexical Environment

Каждый Execution Context содержит собственное лексическое окружение.

Оно хранит:

- локальные переменные;
- параметры функции;
- объявления функций;
- ссылку на внешнее лексическое окружение.

Последняя ссылка называется **Outer Environment Reference**.

Именно она образует цепочку областей видимости.

## Поиск переменных

Когда внутри функции происходит обращение к переменной, движок выполняет поиск по цепочке лексических окружений.

Поиск выполняется в следующем порядке:

1. текущее лексическое окружение;
2. внешнее лексическое окружение;
3. следующее внешнее окружение;
4. глобальное окружение.

Если переменная нигде не найдена, возникает `ReferenceError`.

Этот механизм называется **Lexical Scope**.

## Что такое замыкание

Само по себе наличие ссылки на внешнее окружение еще не является замыканием.

О замыкании обычно говорят тогда, когда внутренняя функция продолжает использовать переменные внешней функции после завершения ее выполнения.

### Пример

```js
function createCounter() {
  let count = 0;

  return function () {
    return ++count;
  };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
counter(); // 3
```

После завершения `createCounter()` переменная `count` не удаляется.

Возвращенная функция продолжает хранить ссылку на лексическое окружение, в котором находится эта переменная.

## Почему переменные не удаляются

После завершения функции ее локальные переменные обычно становятся недоступными.

Однако при использовании замыканий возвращенная функция содержит внутреннюю ссылку `[[Environment]]`, которая указывает на лексическое окружение внешней функции.

Пока существует ссылка на эту функцию, соответствующее лексическое окружение остается достижимым.

Следовательно, Garbage Collector не может удалить содержащиеся в нем объекты.

## Замыкания и Garbage Collector

Garbage Collector ориентируется исключительно на достижимость объектов.

Если существует хотя бы одна ссылка на функцию, а функция содержит ссылку на свое внешнее окружение, то все объекты этого окружения также считаются достижимыми.

После удаления последней ссылки на функцию ее лексическое окружение становится недостижимым и может быть освобождено сборщиком мусора.

## Практическое применение

Замыкания лежат в основе множества возможностей JavaScript.

Они используются при реализации:

- приватных переменных;
- фабрик функций;
- мемоизации;
- debounce;
- throttle;
- обработчиков событий;
- React Hooks;
- модульного паттерна.

Фактически большинство callback-функций в JavaScript являются замыканиями.

## Возможные проблемы

Замыкания могут непреднамеренно удерживать большие объекты в памяти.

Например:

- большие массивы;
- DOM-элементы;
- результаты вычислений;
- объекты состояния.

Если функция продолжает существовать, все эти данные также останутся достижимыми.

Поэтому при проектировании долгоживущих объектов важно понимать, какие данные действительно используются замыканием.

## Частые ошибки

❌ Считать, что замыкание — это просто функция внутри функции.

Замыкание возникает тогда, когда функция продолжает использовать внешнее лексическое окружение.

❌ Думать, что переменные копируются внутрь замыкания.

Функция хранит ссылку на лексическое окружение, а не копии переменных.

❌ Считать, что замыкание сохраняет значения переменных.

Сохраняется ссылка на окружение, поэтому изменения переменных остаются видны всем функциям, использующим это окружение.

❌ Путать момент создания функции и момент создания Execution Context.

Ссылка на внешнее окружение сохраняется при создании функции, а собственное лексическое окружение создается при каждом ее вызове.
