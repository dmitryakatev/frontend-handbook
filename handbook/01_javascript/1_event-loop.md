# Event Loop

Event Loop — это бесконечный цикл внутри браузера (или Node.js), который отвечает за выполнение JavaScript-кода и координирует его работу с остальными подсистемами браузера. Его задача — выполнять задачи в правильном порядке, не блокируя пользовательский интерфейс.

Один цикл Event Loop состоит из нескольких этапов:

1. Выполнение одной **macrotask**.
2. Выполнение всех **microtask**.
3. Выполнение колбэков **requestAnimationFrame**.
4. Обновление страницы (**Render Pipeline**):

   * Layout (Reflow)
   * Paint
   * Composition
5. Выполнение **requestIdleCallback**, если после рендера осталось свободное время.

## Macrotask

За одну итерацию Event Loop выполняется только одна макрозадача.

К макрозадачам относятся:

* пользовательские события (click, input, keyboard и т.д.);
* setTimeout / setInterval;
* сетевые события (например, завершение fetch/XHR);
* MessageChannel;
* postMessage.

После выполнения макрозадачи Event Loop переходит к очереди микрозадач.

## Microtask

После каждой макрозадачи браузер полностью очищает очередь микрозадач.

Если во время выполнения микрозадачи была поставлена еще одна микрозадача, она также будет выполнена в рамках текущей итерации Event Loop.

К микрозадачам относятся:

* Promise.then / catch / finally;
* queueMicrotask();
* MutationObserver.

Именно поэтому длинная цепочка Promise может надолго заблокировать рендеринг страницы.

## requestAnimationFrame

После очистки очереди микрозадач браузер выполняет колбэки requestAnimationFrame.

Этот механизм предназначен для анимаций и синхронизирован с частотой обновления экрана (обычно 60 FPS).

Главное отличие от микрозадач:

Если внутри requestAnimationFrame зарегистрировать еще один requestAnimationFrame, новый колбэк будет выполнен уже на следующем кадре, а не в текущей итерации Event Loop.

## Render Pipeline

После выполнения JavaScript браузер, при необходимости, обновляет страницу.

Рендеринг состоит из нескольких этапов:

* **Layout (Reflow)** — вычисление размеров и положения элементов.
* **Paint** — отрисовка цветов, текста, теней, границ и других визуальных свойств.
* **Composition** — объединение слоев и вывод итогового изображения на экран.

Важно понимать, что Layout выполняется только при изменении геометрии страницы (размеров, позиции элементов и т.д.).

Paint происходит при изменении визуального оформления (цвета, фона, текста и других свойств), а также после Layout.

Composition выполняется видеокартой и объединяет подготовленные слои в итоговое изображение.

## requestIdleCallback

Если после завершения рендера до следующего кадра остается свободное время, браузер может вызвать requestIdleCallback.

Обычно его используют для низкоприоритетных задач:

* аналитики;
* предзагрузки данных;
* кеширования;
* вычислений, которые не критичны для пользователя.

Нет гарантии, что requestIdleCallback будет вызван быстро — если главный поток постоянно занят, его выполнение может откладываться.

## ResizeObserver и IntersectionObserver

Во время этапа рендеринга браузер может вызывать специальные Observer API.

Например, ResizeObserver вызывается после изменения размеров элемента.

Если внутри его колбэка снова изменить размеры этого же элемента, браузер выполнит новый Layout. При постоянном повторении таких изменений может возникнуть ошибка:

> ResizeObserver loop limit exceeded

Это защита браузера от бесконечного цикла перерасчетов.

## Принудительный Layout

Некоторые методы требуют актуальных размеров элементов.

Например:

* getBoundingClientRect()
* offsetWidth
* offsetHeight
* clientWidth
* scrollHeight

Если до их вызова были изменения DOM или CSS, браузеру приходится немедленно выполнить Layout, даже если до этапа рендера Event Loop еще не дошел.

Такое поведение называется **Forced Reflow (Forced Layout)** и может значительно ухудшать производительность при частом использовании.

## Оптимизация

Для плавной анимации рекомендуется:

* изменять transform и opacity вместо width, height, top, left;
* использовать requestAnimationFrame для анимаций;
* избегать частых Forced Layout;
* не создавать чрезмерное количество отдельных слоев (layers), несмотря на аппаратное ускорение.

Для предварительного создания отдельного слоя можно использовать свойство will-change, однако применять его следует только там, где это действительно необходимо.
